# Angelic Angel for Android

Android 17（compileSdk / targetSdk 37）向けの通知ストリームクライアントです。Android 9以上をインストール対象とします。既存のRust CLIと同じMozilla AutoPushへの接続・Xへの受信先登録をAndroid上で行います。PC上のCLIや中継サーバーは不要です。

## インストールと利用

1. `app/build/outputs/apk/debug/app-debug.apk` を端末へ転送してインストールします。開発用署名のAPKです。配布用署名は含みません。
2. Xで対象の相手をフォローし、そのユーザーの投稿通知を有効にします。
3. アプリの「設定」に、ログイン済みブラウザの `x.com` のCookie `auth_token` と `ct0` を入力します。Cookieはパスワードに相当するため、チャットやissueには貼らないでください。
4. 「＋ タブ」で `@ユーザーID` を追加します。最大30タブを保存します。長押しでタブを閉じます。
5. 「受信開始」を押し、Androidの通知権限を許可します。許可後にもう一度「受信開始」を押します。
6. 「X上でも自動ブロックする」を有効にすると、以後自動判定したアカウントへXのブロック操作も送ります。既定では端末内の非表示のみが有効です。

「すべて」には解析できた受信投稿、「@ユーザーID」にはその相手の投稿を表示します。非表示にした相手の過去・今後の投稿は全タブから消えます。「非表示」画面で理由、X上の処理結果、解除操作を確認できます。解除した相手は自動判定の対象外になります。X上のブロック解除はXで行ってください。

## 取得範囲とAPI

- **完全なTwitterクライアントではありません。** 通知に届いた本文だけを蓄積します。過去投稿、フォロー一覧、画像・動画、返信・投稿機能はありません。フォロー状態を照会しないため、タブのユーザーIDは手入力です。
- **API完全不使用ではありません。** 初回登録・UAID失効時の再登録では `/notifications/settings/login.json` を使います。X上のブロックを有効にすると `/blocks/create.json` を使います。既存CLI由来のCookie認証による非公開APIであり、X側の変更やアカウント制限で失敗する場合があります。
- 通知を受け取るためのタイムラインポーリング、HTML取得、スクレイピングは行いません。
- 投稿者を確定できる `/handle/status/id` のURLを持つ通知のみ扱います。相対URLとX/TwitterのHTTPS URLに対応します。DM、既知のリポスト・いいね等の通知、`/i/status/id` のように投稿者を含まない通知は除外します。不明な形式を表示名から推測してブロックしません。
- プッシュは配信を保証しません。省電力、通信切断、X側の通知制御で遅延・欠落することがあります。失った過去の投稿を取得する機能はありません。「再表示」は端末内の履歴を読み直す操作です。
- 明示的に開始するフォアグラウンドサービスで受信し、通知の「停止」で止められます。端末の再起動後はアプリから再開してください。Google Play公開時のspecialUse審査は未実施です。

## 自動判定

単語ルールで、AI関連の投稿に次のうち2種類以上が現れるかを調べます。

- 強い驚き・煽り（衝撃、革命、完全終了等）
- 一律の断定・不安の誘導（誰でも、100%、知らないと損等）
- 反応・拡散の誘導（フォロー、リポスト、無料配布等）

直近10件以内の重複しない投稿に該当が3件以上、かつ半数以上あればアカウント単位で非表示にします。これは文章表現の推定であり、事実の裏付け・虚偽・意図の判定ではありません。引用や批判文の文脈も理解しないため、誤判定時は解除してください。自動判定をオフにしても既存の非表示は残ります。

## 保存と通信

投稿・タブ・判定はアプリ専用SQLite、CookieとPush鍵はAndroid Keystoreを使うAES-GCM暗号化領域へ保存します。クラウドバックアップ・端末移行は無効です。外部のAI判定サービスや解析サービスへ本文を送信しません。保存は最大10,000投稿、画面には直近200投稿を表示します。アプリを削除すると履歴と設定を失います。

別の `auth_token` を設定する際は `ct0` も必要です。その際は端末内の投稿・タブ・判定を消去し、アカウント間で混在しないようにします。

## ビルド

JDK 17、Android SDK Platform 37.0、Build Tools 37.0.0を使用します。Gradle 9.3.1はSHA-256を固定したWrapperが取得します。Android Gradle Pluginは9.1.1です。

Windowsでこの作業環境を使う場合:

```powershell
./scripts/build-android.ps1
```

別環境では `JAVA_HOME` と `ANDROID_HOME` を設定して次を実行します。

```sh
cd android
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --console=plain
```

Windowsでは `gradlew.bat` を使います。初回は依存ライブラリ取得のためインターネット接続が必要です。CIも同じ3タスクを実行します。既存Rust CLIは変更しておらず、このAPKのビルドにはRust/NDKは不要です。

## 検証の範囲

単体テスト、SQLiteの保存・解除テスト、公開RFCの復号ベクトル、模擬HTTP/WebSocketサーバーによる通信テストを収録しています。テストは実際のXアカウントへ接続しません。

実機のAndroid 17、現在のXによる登録受理・実プッシュ配信・実ブロック操作は未確認です。ビルド成功だけで実運用の動作確認済みとは扱わないでください。
